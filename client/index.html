🔑 Pass-by-Value in One Sentence

Java ALWAYS passes by value. Passing an object copies the remote control frequency (e.g. 0x4A2F), NEVER the physical television!

🏛️ 1. JVM Specification Architecture (JVMS §2.5)

Inside the Java Virtual Machine, physical RAM is segmented into two categories:

  • Thread-Private (Stack): Each executing thread has its own private JVM Stack. Contains method execution frames. Threads can NEVER read another thread's stack trays!
  • Thread-Shared (Heap): Single universal memory pool shared across all threads. Synchronized access is required when multiple threads write to the same object.
📦 2. Anatomical Breakdown of a Stack Frame

Every time a Java method is called, an exact frame is allocated containing:

  1. Local Variable Array: Slot 0 = this (for instance methods), Slot 1+ = method parameters, followed by local variables.
  2. Operand Stack: The LIFO workspace where JVM bytecode instructions (e.g. iload, iadd) perform arithmetic.
  3. Frame Data: Reference to the runtime constant pool and method return address.
🎯 3. The 4 Classic Interview Questions
Q1: Is Java ever Pass-by-Reference?
NO. 100% strictly Pass-by-Value. For objects, the "value" is the memory address stored in the variable.
Q2: What happens if you reassign a parameter inside a method?
void test(Dog d) { d = new Dog(); }
The caller's remote is unaffected! You only pointed the helper method's local copy of the remote to a new TV.
Q3: How do you trigger StackOverflowError vs OutOfMemoryError?
• Infinite recursion with no base case → Stack fills up trays → StackOverflowError.
• Creating millions of objects in a loop saved in a list → Heap fills shelves → OutOfMemoryError.
